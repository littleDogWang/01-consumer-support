# 消费电子售后支持设计

## 定位

优先级 P2。验证固定业务数据查询、售后判断和人工接管。

## 目标流程

用户提供订单号或产品信息，Agent 查询固定订单/保修信息，判断是否在保、收集故障描述，给出下一步；查不到记录或需要人工审核时转人工。

## 第一版范围

- 数据：固定 CSV/JSON，字段包括订单号、产品、状态、保修状态和可用售后路径。
- 工具：只读 `lookup_order`。
- 输出：查询结果、建议、人工升级原因。
- 暂不做：真实订单 API、退款、换货写入、物流系统。

## Quickstart 改动点

- 保留现有会话和 UI。
- 在服务端增加 fixture 查询模块和工具契约。
- 若采用 MCP，给 Agent LLM 配置 MCP Server；若 SDK/运行环境未准备好，先用 Prompt 注入固定样本完成流程验证。
- 查询结果不得由模型猜测，必须来自 fixture 或工具返回。

## 失败处理

订单不存在、字段缺失、工具超时都要显示为未查询成功，并转人工或收集回拨信息。
